# 用語：Pythonパッケージからロボットまで

[English](glossary.md) · [文書目次](README.ja.md) · [ビルドの説明](build-fundamentals.ja.md)

何を指す言葉なのか，対象ごとに説明する．部品が存在することと，組込み・検証の完了は異なる．
完了した作業は[進捗](status.ja.md)，配置は[構成の選択](deployment-design.ja.md)を参照する．

## プログラム，プロセス，環境

| 用語 | 意味 | 本プロジェクトの例 |
|---|---|---|
| Source code | 人が読める命令の記述 | 独自の`.py`，本家のモデル実装 |
| Process | メモリと実行期間を持つ，実行中のプログラムの単位 | Jetson上のカメラ受信や一つのPython推論プログラム |
| Runtime | プロセスの実行時に必要なソフトウェア・支援機能 | Python，ネイティブライブラリ，GPU支援．モデルの学習知識ではない |
| Dependency | プログラムが依存するソフトウェア | 推論アダプターが必要とする本家コード・PyTorch |
| API | 関数名・引数・結果など，プログラムから利用する接点の約束 | Pythonのモデルメソッド，ロボットの速度要求 |
| SDK | メーカーがAPI利用のために提供するライブラリ，ヘッダー，例，道具 | B2通信用のUnitree SDK2と，カメラ用のZED SDKは別のSDK |
| Driver | 要求をハードウェアへ伝えるOS・デバイス側の支援 | ホストのNVIDIA・USBドライバ．SDKがそのドライバを使う場合がある |
| CLI / GUI | コマンド行／画面による操作方法 | SSH端末／デスクトップの設定画面 |
| Shell | 端末コマンドを解釈するプログラム | JetsonのBash．Pythonの処理系とは別 |
| Environment variable | 子プロセスへ引き継ぐ，プロセスごとの設定 | `PYTHONPATH`，DDS設定．別のシェルでは値が異なる場合がある |
| ABI | バイナリ単位の呼出し・データ規約 | ネイティブPython拡張は，パッケージ名だけでなく処理系・OSに適合する必要がある |

APIは通信を伴わないローカル関数のこともある．ネットワークAPIなら，プロトコルと到達可能な
サービスも必要になる．SDKは，自動的にサーバー，別の計算機，ROS，機器のファームウェアになるわけではない．

## Python，pyenv，pip，venv，wheel

Pythonは言語であり，その処理系と周辺環境でもある．`python3`で実行する処理系を選び，
`import torch`ではその処理系に設定したパッケージ検索先を調べる．同じ端末でも，
別のPythonを指定すれば別のパッケージ環境を使うことがある．

- **pyenv**はPython 3.11.18などの処理系の版を管理する．GPUドライバを適合させたり，ファイルアクセスを隔離したりしない．
- **venv**は処理系に対応したプロジェクト用パッケージ環境を作る．導入先を分けるが，通信・ファイルへのアクセスは禁止しない．
- **pip**はPython配布パッケージを導入し，宣言された依存を解決する．`python -m pip`なら，指定したPythonに対応するpipを使う．
- **PyPI**はパッケージの配布索引である．配布ファイルと情報を置く場所で，実行中のモデルではない．
- **Build**はソースを導入・実行できる成果物へ変換する処理である．拡張にはC・C++・CUDAのコンパイルが必要なことがある．純粋なPythonの梱包では機械語への変換を伴わない場合もある．
- **Wheel**はPythonの`.whl`配布形式で，メタデータ付きのZIP形式の導入用アーカイブである．純粋なPythonも，コンパイル済みライブラリも入れられる．ロボットの車輪やモデルのチェックポイントではない．

例えば`example-1.0.0-py3-none-any.whl`は，一般のPython 3向けでバイナリABI・OSに依存しない
タグを持つ．説明用の`example-1.0.0-cp311-cp311-linux_aarch64.whl`は，Linux ARM64上の
CPython 3.11とそのABI向けである．ファイル名のタグが適切でも，このJetsonのCUDA，
外部ライブラリ，GPU構成への対応まで保証しない．実際のTorch wheelには，ビルドガイドに
示した実行環境の適合も必要である．[wheelの公式仕様](https://packaging.python.org/en/latest/specifications/binary-distribution-format/)を参照する．

適合するコンパイル済みwheelを入れられれば，通常はそのパッケージを手元でコンパイルせずに済む．
配布物がなければ，ソースからのビルドが必要なことがある．今回は調査したPython・L4T・CUDAの
組合せに対応する構成を管理するため，JetsonでTorch wheel候補を作った．全てのロボット開発で
Torchをビルドし直すわけではない．Docker内にwheelを入れても，ホストのvenvへは入らない．
また，梱包ツールの`wheel`を導入することと，`.whl`で配られる全パッケージを導入することも別である．

## PyTorch，tensor，CUDA，数値精度

**PyTorch**は数値計算・深層学習のライブラリで，Pythonからは`torch`という名前でimportする．
tensor，ニューラルネットワークの演算，学習用の自動微分を提供する．今回はまず，学習済みモデルの
実行に使う．PyTorchは実行用のライブラリで，TIC-VLAそのものではない．
[公式文書](https://docs.pytorch.org/docs/stable/index.html)を参照する．

**Tensor**は多次元配列である．RGB画像を高さ・幅・色チャネルの軸を持つtensorへ変換でき，
重みもtensorとして保存する．行列積などの演算が配列を組み合わせる．形状，データ型，
配置先のデバイスを持ち，GPUがあるだけでCPU上のtensorが自動的にGPU計算されるわけではない．

| 用語 | 意味 | それだけでは証明しないこと |
|---|---|---|
| CUDA | NVIDIAのGPUプログラミング・実行基盤 | ホストGPUドライバやモデルの代わりにはならない |
| CUDA kernel | GPUで並列に実行する関数 | LinuxのOSカーネルとは別 |
| cuDNN | 深層学習ライブラリから使う，最適化したGPU演算 | モデルの重みを提供するものではない |
| torchvision | Torchと組み合わせる画像・モデル用の道具とネイティブ演算 | USBカメラのドライバではない |
| Transformers | 言語・マルチモーダルモデルの構築・実行に使うライブラリ | 特定の一モデルではなく，クラウド呼出しも必須ではない |
| FP32 | 32 bit浮動小数点 | 小さなFP32試験ではモデル品質を検証できない |
| FP16 / BF16 | 指数部と精度の配分が異なる16 bit浮動小数点 | BF16演算の成功だけではモデルの全演算への対応を証明しない |
| INT8 / quantization | 整数表現／手順を定めて表現精度を下げる量子化 | 自動的に精度を維持せず，元の重みの利用条件も消さない |
| Training | 損失・勾配を計算し，学習パラメーターを更新する | Torchのコンパイルや推論で行う処理ではない |
| Inference | 学習済みパラメーターと入力から出力を計算する | 予測した全動作が実機に適切という意味ではない |

**Weights**は学習した数値パラメーターで，**architecture・model code**はそれを使う計算を定義する．
**Checkpoint**はモデル状態を保存したもので，学習情報，optimizer状態，直列化したオブジェクトを
含む場合もある．`.ckpt`・`.pt`などの拡張子だけでは，安全なtensor専用形式とは判断できない．
候補Torchでのチェックポイント読込は確認が済むまで保留しており，オフライン実行や
`weights_only=True`だけでは，記録した脆弱性を解決しない．

## HF，Hub，モデル資材

この環境での**HF**は，`HF_HUB_OFFLINE`のように，通常は**Hugging Face**の略である．
「HQ」は本プロジェクトで定義した構成要素ではない．別の略語は，想定したツールを追加せず，
実際のコマンド・文脈から解釈する．

Hugging Faceにはコード，モデル，データセットのリポジトリがある．**Hub**は配布・アクセスの
サービス，`huggingface_hub`はクライアントライブラリ，`hf`はコマンド行ツールである．
tensorを計算するPyTorchとは役割が違う．Tokenizerは文章をモデル用のtokenへ変換し，
設定ファイルはモデルの構造・設定を記述し，重みは学習した数値を持つ．一つの大きな
チェックポイントだけでなく，これら一式が必要な場合がある．

**Revision**はリポジトリの特定の状態を識別し，**cache**は取得したファイルを再利用する保存先である．
[公式の取得ガイド](https://huggingface.co/docs/huggingface_hub/en/guides/download)は版を指定した取得を説明する．
Jetsonの標準キャッシュはSSDの専用領域を参照し，現在は空である．取得前にファイル，
利用条件，版，サイズを特定して承認する手順であり，本文を読んでもモデルは取得されない．
全入力を承認してローカルへ用意し，loaderも対応すればオフラインで推論できる．
HFはロボットのライブ処理中に呼ぶAPIサーバーとは限らない．

## Dockerとバージョン管理

| 用語 | 本プロジェクトでの意味 |
|---|---|
| Dockerfile | アプリ環境を構築する指示書 |
| Image | ビルドした，保存済みのファイルシステムのレイヤと設定 |
| Container | イメージから作るプロセス環境．ホストのカーネルを共有 |
| Bind mount | ホストの指定パスをコンテナから参照可能にする．読取専用にもできる |
| Docker volume | コンテナの書込レイヤと別に管理するデータ |
| Build context | ビルダーへ渡すファイル群．`.dockerignore`で範囲を制限 |
| Tag / image ID / digest | 変更可能な名前／ローカルの内容識別子／イメージ参照に使う内容識別子．名前だけでなく実際の識別子を残す |
| Git commit | ソースの状態と，履歴・メタデータを記録した単位 |
| GitHub repository | 共有する履歴・共同開発の場所．常時実行するロボットサービスではない |
| Clone / pull / push | Gitのコピーを作る／ソースを取得して統合／コミットした履歴を送信 |
| Artifact | Wheel，イメージ，チェックポイント，レポートなどの成果物．全てをGitへ置くわけではない |

ソースのGit版，イメージの識別子，モデル資材の版は別の事実を示す．実験記録では互いに代用しない．
[配置方針](deployment-design.ja.md)と[ビルドの基礎](build-fundamentals.ja.md)も参照する．

## 通信，ロボット，監督

| 用語 | 具体的な意味 |
|---|---|
| Ethernet / Wi-Fi | 有線／無線のリンク技術．接続だけではIP設定は決まらない |
| Interface / IP / subnet / route | ローカルの通信デバイス／宛先アドレス／アドレス群／パケットの経路 |
| AP / hotspot | Wi-Fiのアクセスポイント．Jetsonで作れば，インターネットなしでもMacをつなげる候補になる |
| SSH / RDP / VNC | 遠隔端末／二つの遠隔画面プロトコル．全て通信経路が必要 |
| Tailscale | 下位の通信を使う，認証・方針と暗号化された到達性．電波は提供しない |
| DDS / RTPS | 型のある分散データ交換・発見／通信上の相互接続プロトコル |
| ROS 2 / node / topic / RMW | ロボット用フレームワーク／参加するプロセス／型のある配信経路／middlewareの抽象化 |
| QoS | 配信・履歴・鮮度などの通信設定．送受信者の対応が必要 |
| Timestamp / clock | 記録した時刻／時刻源．異なる時計をそのまま引き算しない |
| Coordinate frame / transform | 軸・原点の基準／基準間の変換 |
| Pose / velocity / waypoint | 位置・姿勢／運動の変化率／経路上の目標位置 |
| Localization / SLAM | 地図内の自己位置推定／自己位置推定と地図作成 |
| Tracking controller | 経路と現在状態を，動作要求の候補へ変換する処理 |
| Watchdog / expiry | 処理の停止を検知する監視／期限後のデータ・指令の無効化 |
| Supervisor | プロセスの開始・寿命を監督するもの．再起動方針だけでは機体の停止を保証しない |
| Arm / disarm | 研究アプリからの移動要求を明示的に許可／禁止 |
| Deadman / operator override | 継続した操作者の許可を要求／操作者がソフトから制御を取り戻す |
| Emergency stop | 別に確認した物理・システムの非常停止機能．ソフトウェアの停止要求を同等とみなさない |

配線，ドメイン，時刻，実際の停止動作は，このB2で測る必要がある．用語の説明ができても，
接続が動く証拠にはならない．対応する合格条件は[現地手順](field-network.ja.md)と
[オフライン運用](offline-operation.ja.md)に記載する．
