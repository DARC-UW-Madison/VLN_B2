# 独自成果物と上流の研究用ソフトウェアのライセンス

[English](licensing.md) · [文書の目次](README.ja.md) · [外部資料の一覧](../THIRD_PARTY.ja.md)

この文書では，既存のMITライセンスが及ぶ範囲と，公開できるものの判断方法を説明する．
ライセンスの変更や，公開の許可を行う文書ではない．ソースリポジトリ，モデルファイル，
データセット，コンテナイメージ，研究結果は別々の成果物であり，ひとつのライセンス表示で
すべての権利が確認できるわけではない．

## 本家と異なるライセンスを使える理由

ライセンスは，権利者が自分の管理する著作物について利用を許可するものである．
[MITライセンス](https://opensource.org/license/mit)は，著作権表示と許諾表示を残す条件で
広い利用を認める．本リポジトリの[LICENSE](../LICENSE)は，このプロジェクトで独自に作成した
コードと文書に適用する．TIC-VLAの著者や，他の依存先の権利を許可することはできない．

例えば，自分たちの記録した観測を読み，別途インストールされたモデルの公開インターフェースを
呼び出し，自分たちの測定結果を保存する独自プログラムは，モデルを使ったという理由だけで
そのモデル本体の実装になるわけではない．一方，本家の推論関数を自分たちのパッケージにコピーし，
名前を変えても，その部分を自由に別のライセンスへ変更できるようにはならない．
実際の貢献ごとに，出所と関係を確認する必要がある．

したがって，本家とライセンスが異なること自体は誤りではない．ただし，依存先を分けて置くことは，
すべてのアダプターや結合したシステムが法的に独立しているという一律の判断でも，
本家の条件があらゆる利用を許すという判断でもない．実際の内容と適用条件を調べる．

## TIC-VLAの条件で区別すること

確認した[TIC-VLA Academic Software License，リビジョン
`9fa6f8b`](https://github.com/ucla-mobility/TIC-VLA/blob/9fa6f8b66b9e121d5df5df071297bba8e5353ebb/LICENSE.md)は，
学術・非営利の研究者による所定の教育・学術研究目的の利用を認める．
一方で，派生物を含め，ソフトウェアを他者へ再移転することを禁止する．
MITではなく，一般的な再配布の許可でもない．

次の問いを分けて考える：

1. 対象の研究者が，予定する目的のために，適用条件に従って本家の成果物を取得・利用できるか．
2. 対象のソースファイル，改変物，モデル，結合したイメージを，予定する相手へ渡したり公開したりできるか．

研究利用が認められても，移転の問いの答えが自動的に決まるわけではない．
同じ組織に所属するというだけで，別の研究室メンバーへの移転も許可されるとは判断しない．
予定する用途，相手，派生成果物が明確に対象となっていなければ，本家の権利者や
研究室の適切な研究・ライセンス相談先へ確認する．本リポジトリは，その追加許可を得たと主張しない．

制限のあるソースをGitの外に置くことは，誤公開を防ぐのに役立つ．それ自体が，取得，利用，
改変，共有の許可を与えるわけではない．非公開リポジトリ，SSHでの転送，共有SSD，メール添付，
Dockerイメージも，制限のある内容の移転になり得る．名前の変更，翻訳，手入力での書き直し，
AIによる書き換えだけで，独立した権利が成立すると判断しない．

## このプロジェクトでの具体例

| 予定する成果物・操作 | 確認すること |
|---|---|
| 独自に作成した構成調査CLI，合成テスト，説明書 | 著作者と公開権限を確認する．独自部分には本リポジトリのMITを使える |
| 別途インストールした公開APIを呼ぶ独自アダプター | ソースの出所と本家の利用条件を確認する．APIを呼べることは依存先の再配布許可ではない |
| 本家の関数をコピー・改変したソース | コピーした範囲と派生物の条件を特定する．適用される許可なしに自分たちのMIT表示へ置き換えたり公開したりしない |
| ローカルで修正した本家のパッケージ | 元の条件と来歴を保持する．手元での研究利用の許可だけで，差分や結合物を共有できるとはしない |
| 本家ソース，モデル，SDKのバイナリを含むDockerイメージ | 転送前に，含まれる各部品，相手，表示義務，再配布条件を確認する |
| 独自に書いたインストール手順を含むDockerfile | 手順自体と取得する部品を別々に確認する．レシピを公開できても，完成イメージを公開できるとは限らない |
| 論文に記載された手法を独立に実装したもの | 論文を引用し，手法とコピーした実装を区別する．公開前に研究契約や関係する他の権利を確認する |
| カメラの録画，地図，実験ログ | プライバシー，研究室の許可，データの条件，未公開成果を確認する．リポジトリのMITは開示の許可ではない |

これは確認対象の整理であり，未調査の成果物について派生物かどうかを一律に判断する表ではない．
ルートのライセンス名を変えるより，ファイル・成果物ごとに出所を記録することが役立つ．

## 独自のライセンスを新しく作るべきか

現時点では，独自コードと文書にはMITを維持し，本家の制約は別途守ることを推奨する．
研究専用の新しいライセンスを作っても，本家の権利は取得できず，制限のある派生物を公開可能にしたり，
貢献者の所有権を解決したりできない．共同開発者が確認すべき条件がもう一組増えることになる．

将来の独自成果物に別のライセンスを選ぶのは，スポンサー契約や配布方針など，
権利者と研究室に具体的な必要がある場合にする．まず何を許可したいのかを決め，
適切な学内の相談先にその選択を確認する．TIC-VLAのライセンスをコピーして研究室名だけ変更しない．
本家の内容を所有しているわけではなく，その移転制限が自分たちの共同研究方針に合うとも限らない．

MITは，対象となる独自部分について，学術研究以外の利用も許可する．
単なるクレジット表示ではなく，実際の利用許諾である．将来の独自貢献にそのような制約を設けたいなら，
公開前に決める．後からライセンスを変更しても，公開済みのコピーについて既に与えた許可を取り消すものではない．

## 権利者と研究室での権限

既存の共同の著作権表示は，貢献者を示すものであり，大学，研究室，特定個人へ権利を譲渡するものではない．
各貢献者は，選んだライセンスで自分の成果を提出する権限を持つ必要がある．
研究室のGitHubリポジトリを作成したりpushしたりできることは，リポジトリへのアクセス権を示す．
すべての研究成果について，著作権の所有や開示の承認を示すものではない．

[UW-Madisonの著作権・知的財産の案内](https://rsp.wisc.edu/contracts/terms.cfm)は，
研究者の著作権に対する一般的な方針と，スポンサーに関係する義務を説明している．
大学メールやGitHub organizationから権利者を推測せず，実際の雇用・所属，資金，研究協力の契約を確認する．

## 重み，変換，将来の独自研究

モデルの構造を定義するコードは，計算の仕方を表す．重みは，学習したパラメーターを格納する．
チェックポイントには，最適化器の状態，メタデータ，その他のシリアライズされたオブジェクトも入り得る．
これらの条件は互いに異なる場合があり，配布ページのデータセット用ライセンス表示とも一致するとは限らない．
取得・利用の前に，対象ファイル，モデルカード，ソースのリビジョン，適用条件を確認する．

追加学習，量子化，形式変換，パッケージ化をしただけで，元の重みやソフトウェアの条件がなくなるわけではない．
変換スクリプトがMITだからといって，変換した重みにMITを付けない．
新しいコード，学習した重み，評価用録画，論文は，公開を別々に判断する成果物である．

将来の研究では，制限のある外部依存先を明記しつつ，独自のツールや説明を公開できる．
再現のための記録では，制限のあるファイルを同梱せず，本家のリビジョン，取得方法，設定を示せる．
相手が自分に適用される許可に従って取得できる範囲を確認する．禁止された移転を回避するための
許可済み手段だとは扱わない．

## 貢献と公開の手順

予定する貢献ごとに，著作者・出所，必要に応じた正確なリビジョン，独自か改変か，適用条件，
予定する用途を記録する．公開できる依存先情報は[THIRD_PARTY](../THIRD_PARTY.ja.md)に置き，
非公開の許可記録や研究契約は，研究室で承認された保存先に置く．

最初の公開ソースのpushや，その後の成果物の公開前に，次を行う：

1. 実際のファイルとGit履歴について，コピー・制限のある内容，認証情報，個人情報，未公開成果を調べる．
2. 貢献者が独自部分をリポジトリのライセンスで公開でき，研究室・スポンサーの必要な確認が完了していることを確かめる．
3. 公開物にソース，バイナリ，イメージのレイヤー，モデル，データセット，録画のどれを含むか一覧にする．
   ソースだけの確認を，イメージやデータの公開にも流用しない．
4. その成果物と相手に適用される許可・表示義務を解決する．未解決の内容はその公開物に含めない．
5. 確認したリビジョン，条件，公開の判断を記録する．push前にユーザーの公開指示を得る．最初のソース公開は研究室のリポジトリへ行った．以後の成果物の公開でも，この手順を繰り返す．

現在のリポジトリは，本家ソースと重みを公開ソースの外に置く．MITの範囲は独自コードと文書のままである．
この文書で新しい独自ライセンス，本家の再ライセンス，制限のある成果物の再配布許可を導入することはない．
