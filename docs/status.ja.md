# 進捗

[English](status.md) · [ホーム](../README.ja.md)

## 現在の段階

外付けJetsonの初回の読み取り調査を完了した．MacからTailscale経由のSSH，対象機での
構成調査，ネイティブCUDAの数値演算が成功した．AGX Orinの64 GBクラスで，
Ubuntu 20.04／L4T 35.4.1である．CPython 3.11.18，プロジェクト専用venv，CLIを導入し，
対象機で93件のテストと合成データの再生が成功した．別の2 TBのext4パーティションは，
`ro,noload`で調べた後，操作者の明示的な許可で書き込み可能にした．ジャーナルの再生は成功し，
ext4のエラーは観測されなかった．Dockerの保存先と空の標準Hugging FaceキャッシュをSSDの専用領域へ置いた．[実行環境構築](jetson-runtime.ja.md)と
[初回の確認済み構成](target-baseline.ja.md)を参照する．
[システム全体像](system-overview.ja.md)には，正確なストレージ種別，性能，アカウント・コンテナの境界を記した．
GUI起動を維持し，研究用ログインのAC時の自動サスペンドを無効化した．Wi-Fiの自動再試行と
Tailscaleの起動サービスは有効だが，Wi-Fi認証情報のシステム保存と，計画した電源投入からの起動試験は，
操作者による完了が必要である．GUI自動ログインは現地操作用の任意の選択で，起動時の通信には不要である．
共有時はログイン認証を維持する．操作者の希望で，
認証情報の保存と自動ログインの変更は現地まで保留し，現在の接続とGDMのログイン先を維持する．
有線ポートにB2は接続しておらず，モデル推論，カメラ撮影，機体制御は未検証である．
本プロジェクトのCLIは観測またはオフライン処理のままである．監査済みのソースアーカイブは
Jetsonへ転送したが，ソースの公開はまだ行っていない．
公開の研究室リポジトリ[DARC-UW-Madison/VLN_B2](https://github.com/DARC-UW-Madison/VLN_B2)と
push権限を確認したが，pushは未実施である．独自コードと文書には[MITライセンス](../LICENSE)を適用し，
各貢献者がそれぞれの権利を保持する．

開発ホストと対象機での93件のテストを含む確認結果と限界は，
[開発の手引き](development.ja.md#準備段階で実行した確認)に記す．
合成データの再生とモックを使ったテストはソフトウェアの挙動を調べるもので，
実際のドライバー，モデルの品質，ハードウェア性能を確認するものではない．設定例の上限値は運用で承認された値ではない．

起動時ネットワーク用ツールの8件の非通信テストを追加し，開発ホストと対象機で**全93件**が通った．
対象機のシステムPythonで実際の読み取り確認も成功した．認証情報の入力と再接続・起動の検証は，
これらのモック試験には含まれない．

[実行の流れ](runtime-flow.ja.md)に，ソースの同期，本家・重みの別管理，実際のコンテナ内容，
レイヤごとの通信を記した．[認証情報の扱い](system-overview.ja.md#個人の認証情報と共有返却)には，
現地の起動試験と共有・返却前の確認をまとめた．個人の認証情報の保存とGUIログイン先の変更は実施していない．

[文書目次](README.ja.md)をプロジェクトREADMEから分けた．[配置方針](deployment-design.ja.md)，

## 決めていること

[ビルドの基礎](build-fundamentals.ja.md)，[Ethernet・内蔵調査](field-network.ja.md)，
[リモートデスクトップ](remote-desktop.ja.md)の教材・現地準備を追加した．訪問では経路・DDS，
内蔵サービス，外付けUSBと内蔵ネットワークのセンサー経路，起動・画面なしのアクセス，
大学Wi-Fiなしの運用を確認する．記録ひな形にも根拠の欄を加えた．Vinoは導入済みだが待受・プロセスはない．
Tailscaleのクライアント・デーモン1.104.2とTailscale SSH有効を確認した．転送試験前に，
復旧手段を確保して記載した修正版・更新を確認する．画面・ネットワーク・更新設定は変更していない．
将来のローカル実機サービスと通信断時の方針は未実装である．

- 外付け計算機はAGX Orinの64 GBクラスと確認した．B2，ZED 2i，Mid-360の結合は未実施である．内蔵計算機は別に調べ，サービスの担当や配線を推定で確定しない．
- B2の既存の歩行制御を使い，上位のナビゲーション接続部を検討する．
- Macから外付けJetsonへのTailscale経由のSSHを確認した．プロジェクトごとの依存分離を保ち，既存のOS，ROS，ZED，他のアカウントとデータを維持する．機体向けEthernetは未接続である．
- 計画している動作と，検証済みの実装・実験結果を区別する．
- 英語と日本語の文書を保ち，コードと設定は英語にする．
- 公開を想定したファイルには，個人用ラベル，AI専用の指示，チャット全文，機器のアドレス，非公開の研究データを入れない．
- 上流のソフトウェアと重みはリポジトリ外で管理する．コード，重み，データセットが同じライセンスとは限らない．
- 現在のツールにはモーター出力を含めない．観測と同期モデル接続部を検証してから，非同期の移動制御を実装する．
- ファイルと履歴を確認した後，独自成果物をMITで指定の研究室リポジトリへ公開する．利用制限のある上流資料はGitの外に置く．

## 次の成果物

モデル不要の実行環境の段階を完了した．`vln-b2-runtime:jp5`のビルド，`pip check`，
オフラインのTorch検査と全import検査が通った．Python 3.11.18／Torch 2.2.2／torchvision 0.17.2／
CUDA 11.4で，FP32・BF16の8種類のGPU演算を実行し，Transformers，Lightning，timm，
版を固定した本家TIC-VLAをimportできた．モデルは構築せず，ビルド・検査の終了コードはともに`0`である．
重みの取得・読込は行っていない．

次の成果物は，対象のモデルファイルと読込方法の確認である．旧Torchのチェックポイントの脆弱性を解決し，
取得前に具体的なファイル，版，条件，容量，公式キャッシュの保存先について別途承認を得る．
確認後に記録済み観測の推論へ進む．制約は[実行環境の互換性調査](runtime-compatibility.ja.md)に維持する．
並行して，保留した現地の起動・認証情報の検査と，B2の実際の計算機，ケーブル，サービス・ドメインの
確認を進める．移動制御の実装前に，受信だけでの画像・状態取得，座標・時刻，制御権，停止を検証する．

結果は`/mnt/b2-research/VLN_B2/build-logs`の`runtime-build.exit`，`runtime-verify.exit`，
`torch-smoke.json`，`full-smoke.json`へ残す．一回限りの検証ジョブは終了し，モデル取得や
機体のサービスを自動で起動する処理は続かない．初回・再試行のログ，正本から生成した再開用レシピ，
イメージの由来を残した．ローカルのRPC判定の修正とビルド専用wheelの除去は，
[ビルドの再開](jetson-runtime.ja.md#torchのimport判定とビルドの再開)に記す．
保存先と復旧は[構築ガイド](jetson-runtime.ja.md#保存先の前提)を参照する．

Stereolabsには，対応するイメージを選ぶための[Jetson向け公式Docker手順](https://docs.stereolabs.com/docs/integrations/docker/install-on-nvidia-jetson)がある．
NVIDIAは[Jetsonのコンテナruntime](https://developer.nvidia.com/embedded/jetson-cloud-native/)を説明している．
初期構成はZEDのRGB入力，モデル推論，軌道追従，B2 SDKを想定する．
ROS 2とMid-360の接続は，既存のサービスと必要な役割を確認して決める．
[LivoxのROSドライバ](https://github.com/Livox-SDK/livox_ros_driver2)は接続方法の候補であり，採用済みの依存先ではない．
ホストのvenvには本プロジェクトを導入したが，モデルの重みは未取得である．

## 作業を再開する方法

新しい作業は，このページ，関係する手引き，現在のGit差分を読むところから始める．
成果物を限定してブランチを作る．完了時には，根拠，未解決の問い，次の行動をこのページと英語版に反映する．
詳しい実験方法と結果はレビュー済みの報告に残し，このページをセッションの日誌にしない．
